# Дополнительная практика ЛР2

## LR2-P05. Какие файлы можно публиковать, а какие нет?
- Можно: свои файлы с кодом (.ipynb), учебные тексты (.txt, .tsv), описание работы и список версий.
- Нельзя: личные данные (пароли, номера телефонов, почту) и чужие приватные файлы.

## LR2-P06. Проверка личных данных
README.MD не содержит никаких персональных данных.

## LR2-P08. Карточка text_card.md
Вместо этого файла я сделала в папке data табличку metadata.tsv. В ней записаны только безопасные данные: названия файлов, моя фамилия и язык текста.

## LR2-P12. Что сдавать, если GitHub недоступен?
Если Гитхаб не будет работать, я просто упакую всю свою папку проекта в ZIP-архив на компьютере, проверю, что он нормально открывается, и скину этот архив преподавателю на почту или в личный кабинет.

## LR2-X. Задание на повышенный уровень (Сравнение Гитхаба и ZIP-архива):
- Где выше воспроизводимость? На Гитхабе удобнее. Преподаватель может сразу открыть ссылку и посмотреть структуру папок и файлы, ничего не скачивая себе на компьютер.
- Где выше риск ошибочной публикации? В ZIP-архиве накосячить проще. Когда архивируешь папку на компьютере, можно случайно закинуть туда кучу мусора, старые копии файлов или что-то личное. На Гитхабе есть возможность выбрать каждый файл перед загрузкой, поэтому лишнее туда не попадет.

# Итоговое повторение и мини-коллоквиум по модулю

## M01-CQ1. Чем notebook отличается от runtime?
Notebook - это просто файл с текстом кода (как документ Word). Runtime - это временная память компьютера. Если её перезагрузить, компьютер всё забудет, но сам код в файле останется.

## M01-CQ2. Почему порядок выполнения ячеек может не совпадать с их визуальным порядком?
Потому что ячейки в Colab можно запускать мышкой в любом порядке,прыгать снизу вверх или запускать одну ячейку по несколько раз.

## M01-CQ3. Что доказывает Restart/Run all?
Он доказывает, что код работает правильно строго сверху вниз. 

## M01-CQ4. Какой раздел README помогает воспроизвести проект?
Раздел «Инструкция по запуску». Там написано, куда нажать и какие файлы загрузить, чтобы всё заработало.

## M01-CQ5. Что считается достаточным доказательством индивидуального понимания?
Когда ты можешь своими словами объяснить, зачем нужна каждая папка в твоем проекте и почему в названиях файлов нет пробелов.

## M01-CQ6. Что нельзя публиковать в открытом репозитории?
Личные данные: свои и чужие номера телефонов, пароли и секретные ключи доступа.

## M01-CQ7. Почему Git-lite не равен полному Git?
Git-lite - это простая загрузка файлов через кнопочки на сайте GitHub в браузере. Полный Git - это сложная работа через командную строку на компьютере.

## M01-CQ8. Какой тест вы добавите к project capsule?
Тест на распаковку архива в новой пустой папке, чтобы проверить, что относительные пути к файлам данных (../data/) не сломались и код запускается.
